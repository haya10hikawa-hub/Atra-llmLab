# g12L2 — Gemma-4-12B-it への LoRA（Formation + Personal）と、LoRA は必要か

- **Verification:** `VERIFIED_LOCAL`（2026-10-24、学習は AWS の GPU 1 枚、評価はローカル。再学習 1 回）
- **Model:** google/gemma-4-12B-it + LoRA（r16、alpha 32、language-model の q/k/v/o + gate/up/down）。配備は QAT Q4_0 GGUF + LoRA GGUF（`llama-server --lora`）。HF（private）: Atra-LLMlab/atra-gemma4-12b-research
- **Goal:** zero-shot Gemma に Atra の Formation/Personal の形式を LoRA で教え、dev3（合成）で Jev 相当、実データで zero-shot 以上を狙う。
- **Baseline:** zero-shot（[g12-gate](g12-gate.md)）。
- **Prediction（事前）:** dev3 argmax ≥ 0.85 かつ false merge ≤ 10。dev_real AUC ≥ 0.90 かつ zero-shot から 0.02 以内。
- **Change:** LR 2e-5 cosine、clip 1.0、2 epoch / 700 steps（72.6 分）。混合 iw .15 / sel .30 / cs .04 / Personal .26 / 汎用 typed-decision .25（公開データ 3,750 件）。Jev・教師の soft target なし、JevBench 項目なし、実データなし。

## 失敗した初回（無効 Run）
LR 1e-4・clip なしは step 約 250 で発散（label mass 0.05、dev3 .32）。結果として扱わず、上の設定で再実行した。

## Step 1：LoRA は必要か（C0 = zero-shot + 閾値補正 vs C1 = LoRA、dev3 の 2 分割交差適合）
zero-shot QAT .605 / FM 15（FM ≤ 2 は達成不能。≤ 8 への緩和は事後の変更）、LoRA .827 / FM 8。実データでは zero-shot が優位、dev3（合成、LoRA の学習と同系統）では LoRA が優位で、**証拠が食い違う**。判定は Full Replay（[g12L2-replay](g12L2-replay.md)）に委ねた。

## Personal の閾値補正（2026-10-24）
dev3 Personal 179 件、raw argmax：verdict .860、false DONE 4、見逃し REQUIRED 8、誤検出 REQUIRED 13。4 分割交差適合の閾値補正（SPURIOUS_COST 1/2/3）は誤検出 REQUIRED が 16/16/15 で、改善しない。

## Decision
LoRA 付き（QAT Q4_0 + g12L2）を採用候補とする。実データでの優位性は主張しない。

## Risks / 未検証
- 実データでの Formation 4 分類の性能は UNKNOWN。dev_real（ペア AUC のみ）では zero-shot 以上にならなかった。
- 単一 seed、dev3 のラベルは Claude 作成（人手 Gold ではない）。
- 汎用データ（MNLI/BoolQ/BANKING77/CommonsenseQA/ARC/HellaSwag/SST-5）のライセンスは未検証。Personal ラベル（`consensus_v3`）の来歴は、case ごとの basis 欄より先は不明。公開用 Adapter としての審査が必要（HF は private）。
